# Research: извлечение правил из PDF

Дата: 2026-10-23. Источник: `Witcher.pdf` (337 стр., 85.6 МБ, ABBYY FineReader PDF 15, ISBN 978-5-907170-26-1).

## 1. Что внутри PDF

- 337 страниц, текстовый слой присутствует на всех страницах (это не скан без OCR).
- Текст распознан качественно: абзацы, заголовки, таблицы в основном читаются.
- Есть мягкие переносы, колонтитулы, номера страниц, буквицы и декоративные элементы.
- Иллюстрации и цветные иконки — отдельные изображения; OCR их не видит.
- Оглавление на стр. 3 свёрстано в три колонки, поэтому в тексте перемешано. Страницы разделов восстановлены по оглавлению.

## 2. Качество извлечения

Проверено `pypdf` (raw + layout), `pdfplumber` (words/tables), рендер страниц через `pypdfium2`.

### Что извлекается хорошо

- Одноколоночный текст правил.
- Карточки заклинаний, знаков, ритуалов, порчи, инвокаций: устойчивый шаблон
  `Название → Затраты Вын → Эффект → Дистанция → Длительность → Защита`.
- Числовые таблицы при извлечении по координатам слов (x/y), а не по линиям.
- Таблицы брони, оружия, транспорта, компонентов, чертежей.

### Что ломается

1. **Двух- и трёхколоночная вёрстка.** В raw-тексте колонки идут вперемешку; layout-режим сохраняет колонки, но боковые врезки всё равно вклиниваются.
2. **Таблицы без векторных линий.** `pdfplumber.extract_tables()` возвращает 0 таблиц почти везде: линии — часть фонового изображения. Нужен собственный парсер по координатам слов.
3. **Иконки в формулах алхимии.** Колонка «Ингредиенты» на стр. 146–147 — цветные иконки 9 субстанций, OCR выдаёт мусор (`©`, `О`, `ФввСоЗвво`). Нужно распознавать цвета/формы по рендеру страницы или переносить вручную. Легенда иконок — стр. 142.
4. **Опечатки OCR в бросках:** `1Л6`, `ld6`, `1 d6`, `IdlO`, `1 dlO`, `KpoH`, `С Л`, `Юи более`. Исправляются регулярками + сверкой с изображением.
5. **Многоколоночные списки заклинаний** (стр. 101): уровень и стихия заклинания задаются положением в таблице, а не текстом карточки. Нужно строить индекс «имя → уровень/стихия» из стр. 101.
6. **Древа навыков** (стр. 61–70): способности расположены блоками по ветвям, читаются хуже остального; потребуется ручная сборка.
7. **Врезки и цитаты** (Родольф Казмер, Брендон из Оксенфурта) вклиниваются в основной текст. Их нужно выносить в `<Aside>`.

## 5. Веб-источники

- Фандом: только обзорная статья и отдельные карточки, систематических правил нет. Сохранено в `web/fandom_*.json`.
- Foundry VTT, официальная система: `lang/ru.json` — русская UI-терминология (не текст правил), `template.json` — удачная схема данных предметов. Сохранено в `web/`.
- Foundry-компендиум (английский, фанатская сборка официального контента): полезен для сверки структуры и чисел, но не для русского текста. Ссылка в `web/sources.md`.
- Готового структурированного русского датасета не найдено.

## 6. Предлагаемый конвейер

1. `extract`: постранично сохранить текст (raw + layout), координаты слов, при необходимости PNG 150–200 dpi.
2. `normalize`: убрать колонтитулы/номера, склеить переносы, исправить OCR-артефакты, разметить врезки.
3. `structure`: 
   - правила → Markdown;
   - каталоги → YAML/JSON по схемам;
   - таблицы → парсер по x/y + ручная сверка;
   - формулы → распознавание иконок по цвету + сверка.
4. `verify`: 
   - покрытие: каждое предложение исходной страницы должно найтись в готовом тексте (нормализованное сравнение);
   - схемы: Zod-валидация, уникальность, допустимые значения;
   - выборочная сверка с рендером страниц.
5. `build`: VitePress собирает статику, Vercel деплоит.
